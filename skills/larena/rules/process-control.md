# Process Control

## Mirai Graph Hybrid Entry

For substantial Larena tasks use repo-local `graph/specs` and the latest Mirai
Graph runtime context as the first machine-readable index for capability
selection, routing, readiness, companion contracts and scenario evidence. The
graph may choose the owner boundary, required gates, related skills and the
raw-source fallback path.

Raw `larena` sources stay authoritative for methodology, judgement, sensitive
rules, reporting format and final domain verdicts. Sensitive, runtime, security
and safe-write decisions require raw-source fallback and the relevant owner
gate. Platform-specific detail stays in the owner skill; the central graph may
point to it but must not absorb it. This is Hybrid SOT, not graph-only runtime.

## Executable Process Control

Larena package work is the domain realization of the Mirai Graph development
conveyor: Larena DNA, package specs, launch record, allowed files, evidence
package, graph sync proposal, review gates and runtime feedback.

- Do not start package coding from a markdown plan alone; require the process
  contract and Larena/package source-of-truth context.
- Package work passes the active state-machine transition before coding,
  release or acceptance claims. A spec or plan prepares the human projection;
  a coding batch starts only from launch record scope, allowed files,
  action-gate result and evidence path.
- Recovery resumes from workflow, launch record, evidence and git state, not
  from chat memory.

## Pre-Codegen Repository Preparation

Before writing implementation code in any Larena package repository, load and
obey [../knowledge-packs/package-pre-codegen-repository-preparation.md](../knowledge-packs/package-pre-codegen-repository-preparation.md).

- A legacy repository with confirmed backup is emptied in the active tree and
  rebuilt as a clean Larena package repository.
- Preparation covers package identity, specs reference, launch context,
  Composer command contract, hooks, CI, scope checker, evidence paths,
  graph-sync proposal boundary and validation before `ready_to_code`.
- Installing enforcement on top of old active code is not enough.
